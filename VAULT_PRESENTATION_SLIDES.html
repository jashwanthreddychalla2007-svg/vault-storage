❓ The Problem Statement: Hardware Unreliability
PART 1: INDUSTRY REALITY

Physical storage servers (HDDs, NVMe SSDs) in data centers fail every single day. Traditional single-server storage setups lead to catastrophic business data loss.

1. Unannounced Server Crashes
Hard drives overheat, power supplies explode, or network cards fail. If files sit on a single server that dies, business data is lost forever.
2. Silent Bitrot Data Corruption
Magnetic layers on physical disks naturally decay over time (bits flip from 1 to 0). Files corrupt silently without triggering drive alerts.
3. Single Point of Failure
Storing files on one physical server rack means a single power outage or cable disconnect takes down the entire application.
4. Unpermitted Security Leakage
Without strict server-side multi-tenant authorization, unauthorized API requests or users can inspect or delete restricted files.

💡 The Solution: Vault Self-Healing Engine
PART 2: VAULT ARCHITECTURE

Vault turns a cluster of cheap, unreliable physical storage nodes into a 100% durable, self-healing data fortress.

Multi-Rack Replication
Duplicates payloads across 3 independent physical racks (rack-1, rack-2, rack-3) to survive full rack outages.
Anti-Entropy Auto-Repair
Background scrubber sweeps every 5 seconds, detects missing or bitrot-corrupted blocks, and re-replicates clean copies automatically.
Quorum Consensus
Enforces W + R > N quorum rules (N=3, W=2, R=2) to prevent write skew and split-brain reads during network latency.
[Upload Payload] -> SHA-256 Merkle Root Digest -> CRUSH Rack Allocator -> Write Quorum Confirmed (201 Created)

🔄 Causal Life Cycle of a File in Vault
PART 3: STEP-BY-STEP FLOW
1. UPLOAD PHASE:
User uploads file -> SHA-256 Merkle hash calculated -> Placed on Node-1 (Rack 1), Node-3 (Rack 2), Node-5 (Rack 3).
2. CHAOS SIMULATION (Node Crash):
Node-3 set OFFLINE -> Cluster enters DEGRADED state (2/3 Replicas surviving).
3. ZERO-DOWNTIME QUORUM READ:
User requests download -> Quorum Read (R >= 2) fetches file from Node-1 & Node-5 -> File downloads perfectly!
4. AUTOMATIC ANTI-ENTROPY REPAIR (5-Second Sweep):
Scrubber detects missing replica -> Copies block to Node-2 -> Checks SHA-256 digest -> Restored to 100% HEALTHY!
